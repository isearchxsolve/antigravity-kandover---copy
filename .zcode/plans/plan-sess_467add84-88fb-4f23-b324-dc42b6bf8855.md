## Audit result: the engine is ~90% there — a few high-impact gaps break "Hollywood grade" + "zero runtime defects"

I traced the full pipeline (`run.py` → preflight → forge → cost-meter → render_stills/render_motion → postprocess → grade → stitch → master) and confirmed these defects by file:line. Each is real (not speculative). Fixing them is what moves the engine from "stylized cinematic" to "Hollywood-grade, zero end-to-end defects."

### Defect 1 — CRITICAL: the quality gate is never enforced
`qc.py` is a full objective gate (resolution / fps / black-frame / freeze / loudness / sharpness / flicker), designed to "exit non-zero if ANY shot FAILs." But `run.py` never calls it (**0 references**). So a shot with a **black segment, frozen frame, or blown LUFS silently ships into the final film.** `selftest.py:168` runs it; production does not.
→ **Fix:** wire `qc.py` as a hard gate in `run.py` between render (stage 6) and stitch, and re-run it on the final master. On FAIL → abort before mux, listing offending shots. (`run.py` stage area + a final-deliverable check)

### Defect 2 — CRITICAL: postprocess fallback reintroduces the exact artifact trap that was "permanently fixed"
`postprocess.sh:65` has the `NEED_INTERP` guard (skips optical `minterpolate` when target ≤ source×1.2) — the documented #1 morph/tear fix. But `render_motion.py`'s **Python/Windows ffmpeg fallback runs `minterpolate=...mi_mode=mci...vsbmc=1` unconditionally** (`render_motion.py:358`). On Windows or any host without bash, every shot gets warped/morphed frames — the very defect the kit claims to have permanently fixed.
→ **Fix:** mirror the `NEED_INTERP` guard in the Python fallback: skip interpolation when `fps ≤ srcfps×1.2`; otherwise use conservative `minterpolate` settings (drop `vsbmc`, the worst morph offender). (`render_motion.py:_do_postprocess`)

### Defect 3 — CRITICAL: cross-shot normalization is missing in stitch
`stitch.py` concatenates with the **concat demuxer and zero normalization** (`stitch.py:133-137`). The demuxer silently corrupts (dropped frames / wrong timing / broken stream) unless every shot shares codec, WxH, fps, SAR, and pix_fmt. With per-shot `upscale`, mixed stills/motion paths, and identity retries, dims/fps can differ across shots. Only the finale-append path uses `scale2ref/setsar/fps` (`stitch.py:346-350`) — the main body doesn't.
→ **Fix:** pre-normalize every shot to a common canvas (target WxH from config, `setsar=1`, common fps, `yuv420p`, BT.709) before concat. Single biggest "Hollywood-grade cut" fix.

### Defect 4 — HIGH: the configured film look is silently dropped
`grade_match.py`'s `__main__` branch is inverted (`grade_match.py:345-372`). The postprocess call is `grade_match.py IN OUT GRADE` (**3 args**), which falls into the `else` branch (line 367) that treats `argv[3]` as a **preset name** instead of the JSON target path. Result: `refs/grade_target.json` is never read, so the calibrated color look (`kodachrome`/`arri_aces`/etc.) is ignored and the grade uses the hardcoded `kodachrome` default.
→ **Fix:** correct the branch so the 3-arg postprocess path reads `argv[3]` as the JSON target and passes the resolved preset into `grade_video`.

### Defect 5 — HIGH: take selection is not actually identity-aware (dead code)
In `render_motion.py` the identity retry computes `last_best` but **`best = _pick_best(takes)` is always called and `last_best` is never used** (`render_motion.py:242-257`). So identity scoring runs but the chosen take can still be the wrong face. This is the documented "Kunal/Gunja look the SAME across every shot" guarantee — currently not enforced.
→ **Fix:** prefer a take that passes the identity threshold; only fall back to `_pick_best` among passing takes (or all takes if none pass).

### Defect 6 — MEDIUM: no per-shot loudness conformance (amateur tell)
`stitch.py` runs `loudnorm` once on the final mix, but per-shot voice clips are not loudness-conformed → audible level jumps between shots. The master chain's true-peak limiter values I'll also verify are broadcast-safe.
→ **Fix:** add per-shot voice loudness conformance (EBU R128 target from config, default −16 LUFS) in the voice stem build, with a gain-only pass (no dynamics) so it doesn't fight the master chain.
